# Golden Paths

These delivery paths are governed by the root [Fabric Engineering OS Constitution](../CONSTITUTION.md). They turn approved intent into reviewable evidence; they do not replace workload-specific judgment or current [Microsoft Learn](https://learn.microsoft.com/fabric/) validation.

| Path | Outcome |
| --- | --- |
| [Source onboarding](source-onboarding.md) | A governed source ready for repeatable processing |
| [Data product](data-product.md) | A contract-tested medallion data product |
| [Mirroring to gold](mirroring-to-gold.md) | Supported mirrored data refined into stable gold |
| [Semantic model](semantic-model.md) | A governed, performant semantic interface |
| [Eventhouse RTI](eventhouse-rti.md) | A validated low-latency event solution |
| [Data agent](data-agent.md) | A bounded agent grounded in approved Fabric data |
| [Metadata-driven ELT](metadata-driven-elt.md) | Reusable multi-source ELT with auditable state |
| [Production incident](production-incident.md) | Controlled restoration with preserved evidence |
| [Release management](release-management.md) | Reproducible promotion with human production control |

Across every path, agents may implement and use approved workflows to deploy DEV and TEST. Humans approve architecture, pull requests, merges, and PROD actions. Approval cannot be inferred from successful automation.
