# Frequently Asked Questions

This FAQ is governed by the [Fabric Engineering OS Constitution](../CONSTITUTION.md).

Answers route to canonical documents when a rule or process is involved.

## Can I use another data platform?

No. Fabric Engineering OS supports Microsoft Fabric only. See the canonical [Constitution](../CONSTITUTION.md).

## Which sources should I trust?

Microsoft Learn is authoritative for Microsoft product behavior. Skills for Fabric is preferred expertise, Fabric Accelerator is the primary architecture reference, FMD is the primary implementation reference, ELT is secondary, and Fabric Toolbox is optional discovery. See the [Constitution](../CONSTITUTION.md) for the canonical order.

## May automation update those upstream sources?

No. Upstream sources and repositories are read-only references and are never automatically modified or synchronized.

## What may an agent do?

Within approved scope, an agent may help create issues, branches, commits, pull requests, and DEV/TEST evidence. It may not self-approve, merge, release, deploy to production, autonomously change this OS, or modify upstream repositories. See [Governance](../GOVERNANCE.md).

## Who approves architecture, merge, release, and production?

Accountable humans do. Decision roles are in [Governance](../GOVERNANCE.md), maintainer responsibilities in [Maintainers](../community/MAINTAINERS.md), and publication steps in the [Release Strategy](../community/RELEASE-STRATEGY.md).

## Does a roadmap item guarantee delivery?

No. A roadmap item expresses accepted direction; an item in the [Ideas Backlog](../community/IDEAS-BACKLOG.md) is even earlier and has no commitment. Delivery is evidenced by a human-approved merge and human-published release.

## Where do I start?

Use [Getting Started](Getting-Started.md), then select a checklist from the [Bootstrap Guides](../bootstrap/README.md).

## Can DEV or TEST promotion be automated?

Only through approved, auditable workflows with required human authorization. These permissions do not extend to production. The selected [Bootstrap Guide](../bootstrap/README.md) defines the evidence and gates.

## Where should product-specific details live?

Link to current Microsoft Learn content and record project-specific assumptions in an issue or decision record. Do not copy large upstream guidance into this wiki. Use the [Contribution Guide](../community/CONTRIBUTING.md) for evidence expectations.
